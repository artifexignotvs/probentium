## Automated checks

147 tests pass in the current source tree. The suite covers known parser/time outcomes, malformed and oversized inputs, ambiguous temporal relations, coverage and duplicate-source behavior, hypothesis counterevidence, public-report allowlists, provenance/diff validation, resume checkpoints, evidence replacement, source-path traversal, raw terminal controls, narrow screens, bounded triage summaries and exclusive output under races/crashes.

Critical source intake and report logic received separate reviewer passes. Review reproduced a hash/reopen race and a stored-source path-validation defect and a replay ceiling defect for imports above one million records; these were corrected and retained as regression cases. Output writing was changed to publish a complete private file atomically without overwriting an existing target. Tests include real subprocess termination around publication. These reviews are development checks, not independent certification.

Eight synthetic timestamp conversions agree with GNU date at the UTC microsecond lower bound, including pre-epoch time, non-hour offsets, leap-day dates, post-2038 time and submicrosecond input. See [recorded reference results](time-reference-results.json) and `scripts/check_time_reference.py`. This checks timestamp conversion only. No comparison of SSH/journal artifact interpretation against a full independent forensic suite has been completed.

## End-to-end results

Both synthetic scenarios complete intake, analysis, hypotheses, reports, snapshots and verification. Each contains ten parsed records from two files and two findings. The authentication-after-failures finding is certain within its interval model in both. The process relation changes from certain to possible under the declared ±30-second process-clock error.

Replay reproduces normalized records and analysis. A new case identifier is expected. A full report refuses changed evidence. Shared output omits the fixture's IP, host, actor, path and free text while retaining linked pseudonyms and explicit residual privacy limitations.

The actual TUI was recorded in a pseudo-terminal, and timeline/detail/raw frames were visually inspected. The cast records real program output; synthetic data is generated by the same installed command users can run.

## Packaging

The wheel and source archive are installed in separate clean virtual environments. The packaged tests and two synthetic scenarios are checked outside the source checkout. Release archives normalize owner/group fields and build timestamps so local account metadata is not distributed. `scripts/build_release.py` records package hashes; its fixed archive timestamp is a reproducibility setting, not an acquisition time. The current public core is licensed under Apache-2.0. See [licensing](licensing.md) and the package license files.

## What these checks do not establish

No courtroom admissibility, acquisition authenticity, complete chain of custody, measured detection precision/recall, guaranteed anonymity, broad artifact support, multicore scalability or superiority over another forensic product is claimed. The benchmark is a reproducible local sparse synthetic workload, not a production capacity promise.
